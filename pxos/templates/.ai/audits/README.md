# Codebase Audits Directory
<!-- pxos:audits:guide -->

This directory stores structured audit reports generated by AI agents (acting as Principal Auditors via `/audit`) or human engineers.

---

## File Naming Conventions

- **Full System Audits:** `AUDIT_YYYY-MM-DD.md` (e.g. `AUDIT_2026-09-04.md`)
- **Modular Subsystem Audits:** `PARTIAL_<subsystem>.md` (e.g. `PARTIAL_auth.md`, `PARTIAL_audio_engine.md`, `PARTIAL_electron_ipc.md`)
  *Note on scalability:* In large codebases (50k+ lines), run `/audit` per subsystem to protect context window limits.

---

## Finding Severity Levels

| Severity | Definition | Workflow Impact |
|---|---|---|
| **P0 — Blocker** | Security vulnerability, data loss risk, runaway memory leak | Blocks new features on the affected subsystem until resolved |
| **P1 — Critical** | High failure risk, severe performance degradation, broken invariant | Must be prioritized in current or next sprint |
| **P2 — Major** | Technical debt, architectural coupling, missing error boundaries | Tracked and addressed during related feature work |
| **P3 — Minor** | Code smell, naming inconsistency, non-blocking polish | Low priority cleanup |

---

## Finding Entry Template

```markdown
### [FINDING-ID]: [Short Title]
- **Severity:** P0 | P1 | P2 | P3
- **Category:** Security | Performance & Memory | Architecture | Quality & UX
- **Location:** `path/to/file.ts#L42-L68`
- **Description:** [What the issue is and why it matters]
- **Evidence / Reproduction:** [Code snippet or profiling observation]
- **Remediation:** [Concrete steps to resolve]
- **Status:** Open | In Progress | Resolved
```

---

## Operational Protocol

1. **Auto-Grounding:** When `/spec` runs, the agent checks this folder for open findings touching the targeted files.
2. **Resolution:** When `/plan` runs, any addressed audit findings are cited (e.g. "Resolves SEC-01").
3. **Closing:** Once resolved and reviewed via `/review`, the finding's status is updated to `Resolved`.
