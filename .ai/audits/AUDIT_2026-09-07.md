## Detailed Subsystem Findings & Architectural Analysis

### Subsystem 1: Telemetry & Empirical Benchmarking Server
- **Files:** `benchmarks/server.py`, `benchmarks/analyze.py`, `scripts/pxos-benchmark.py`, `scripts/pxos-telemetry-monitor.py`
- **Security & Privacy (`INV-001`):** Project names are irreversibly SHA-256 hashed on client dispatch (`project_hash`). Payload sanitization whitelists allowed schema keys, bounds string lengths, and strictly ignores extra JSON properties.
- **Deduplication:** Cryptographic `session_fingerprint` uniquely indexed in SQLite with `ON CONFLICT(session_fingerprint) DO UPDATE` to prevent Sybil benchmark flooding.
- **Plausibility Anti-Spoofing:** Verified guards reject impossible submissions (e.g. active turns with 0 tokens, rework turns with 0 rework LOC, or throughput exceeding human/agent threshold of 2,000 LOC/turn).
- **Concurrency & Memory:** Proactive sliding-window eviction purges stale IP and project tracking dictionaries when size exceeds 500 entries, with hard caps at 10,000 entries. Database connections use thread locks, WAL journal mode, and 5,000ms busy timeout.

#### [SEC-03]: Project Rate Limiter Bypass on Literal `'anonymous'` String
- **Severity:** P3 — Minor
- **Category:** Security & Rate Limiting
- **Location:** `benchmarks/server.py#L53-L84`
- **Description:** Previously, `is_project_rate_limited()` bypassed daily quota checks if `project_hash == "anonymous"`.
- **Remediation:** Removed the `"anonymous"` exemption in `server.py` and `pxos-benchmark.py`. All project submissions, including anonymous hashes, are uniformly governed by the 10-submissions/day project quota.
- **Status:** Remediated & Verified

#### [REL-08]: Deterministic Git Extractor Fallback on Single-Commit Repositories
- **Severity:** P3 — Minor
- **Category:** Reliability & Edge Cases
- **Location:** `scripts/pxos-benchmark.py#L136-L143`
- **Description:** In newly initialized repositories with exactly 1 commit, `git diff --numstat HEAD~1` fails because `HEAD~1` does not resolve.
- **Remediation:** Implemented deterministic fallback: diff against the empty tree hash (`4b825dc642cb6eb9a060e54bf8d69288fbee4904`) to compute initial LOC additions cleanly without errors.
- **Status:** Remediated & Verified

### Subsystem 2: Core CLI, Doctor & Invariant Evolution Engine
- **Files:** `pxos/cli.py`, `scripts/pxos-invariant.py`, `pxos/scripts/pxos-invariant.py`, `scripts/pxos-task.sh`, `scripts/pxos-task.ps1`
- **Zero External Core Dependencies (`INV-003`):** Verified 100% standard library Python (`argparse`, `urllib.request`, `subprocess`, `hashlib`, `re`, `json`). No third-party packages required.
- **Invariant Evolution:** Validates sequential monotonic invariant IDs (`INV-001` through `INV-005`), regex integrity, and imperative keywords (`must`, `never`, `always`). Cognitive post-mortem failure classification (`ASSUMED_CONSTANT`, `MULTI_NODE_BLINDNESS`, `PREMATURE_COMPLETION`) synthesizes targeted invariant recommendations when rework ratio exceeds 20%.
- **Duplicate Prevention:** Jaccard keyword similarity check rejects candidate rules with >70% overlap against existing invariants unless `--force` is specified.
- **Task Automation:** Git worktree creation scripts properly sanitize multi-slash branch names (e.g. `feat/ui/dashboard` -> `feat-ui-dashboard`) and seed modular specs from template.

### Subsystem 3: Public Benchmark Portal & Research Dashboard
- **Files:** `templates/site/public/benchmarks/index.html`, `dashboard.css`, `dashboard.js`
- **Architecture:** Zero-build static web application compatible with GitHub Pages, Cloudflare Pages, and static hosting. Consumes `/api/v1/stats`.
- **Chart Lifecycle & Memory Management:** Verified that Chart.js canvas instances are destroyed via `.destroy()` before new instances are created upon filter toggles, eliminating canvas memory leaks.
- **XSS Sanitization:** All dynamic user/model inputs rendered in the runs table are strictly escaped via `escapeHtml()`.
- **Open Science Export:** Verified client-side JSON and RFC 4180 CSV generators produce well-formed, sanitized downloadable datasets without network dependencies.

#### [UX-01]: Manual Re-poll Trigger on Offline Indicator
- **Severity:** P3 — Minor / Enhancement
- **Category:** UX & Resilience
- **Location:** `templates/site/public/benchmarks/dashboard.js#L197-L209`
- **Description:** When network calls to `/api/v1/stats` fail, the portal automatically falls back to `BASELINE_DATASET` and polls every 60s. Adding a clickable cursor and event listener directly to `#network-status` allows developers to trigger an immediate reconnect attempt without refreshing the browser tab.
- **Remediation:** Add `cursor: pointer` style and a click handler to `#network-status` that invokes `fetchTelemetryData()`.
- **Status:** Documented / Enhancement Opportunity
